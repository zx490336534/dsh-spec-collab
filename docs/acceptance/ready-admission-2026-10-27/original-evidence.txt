7: ## 核心流程
8: 
9: ```text
10: 输入原始需求
11:   -> 产品 AI 自动初审（九个维度）
12:   -> 产品逐项回应
13:   -> 产品 AI 二次审核 + 候选 patch
14:   -> 产品确认当前 commit
15:   -> 产研 + 双方 AI 共审
16:   -> 产品/研发分别确认当前 commit
17:   -> 六项 Ready 门
18:   -> 输出 Ready Spec
19: ```
20: 
21: ## 能力
22: 
23: - 匿名只读；首次评论、修改、回复、确认前登记 `participant_id + 花名 + 责任角色`。
24: - 原始需求、Markdown PRD、相关链接与代码范围分别记录为来源，不静默混成事实。
25: - 正式正文只存在 `requirements/<id>/spec.md`，每次显式保存生成一个 Git commit。
26: - 保存携带 `baseCommit`；过期或存在外部未提交修改时拒绝覆盖。
27: - `FACT / INFERENCE / ASSUMPTION / TO_VERIFY` 结构化 Review Item；`FACT` 强制可访问且带版本的证据。
28: - 产品 AI 初审、产品 AI 二审、研发 AI 预审、变更审核四类独立 DSH review session。
29: - 每条实质评论提交后自动启动 AI 分析，回复必须包含理解、证据或 `TO_VERIFY`、影响章节/AC 和建议处置。
30: - AI 只能提交 Review Item、评论分析和候选 patch；不能写 Git、代替人确认或标记 Ready。
31: - 保存和 patch 接受后自动触发 change review；候选 patch 基于精确 commit，过期自动失效。
32: - Decision、Comment、Confirmation 分离；确认绑定 commit，可按 section/AC 局部失效。
33: - Ready 门检查目标与用户结果、稳定 AC、范围与非范围、业务语义、证据来源、测试约束。
34: - Ready 输出包含 commit SHA、稳定 AC、Decision、来源、非阻塞 Open Questions 和产品/研发确认人。
35: - Agent 工具：`spec_list`、`spec_read`、`spec_reply`、`spec_submit_review`、`spec_propose_patch`。

25: 处理审核项时遵循以下规则：
26: 
27: - 有业务结论时选择推荐方案或自行输入，并说明取舍。

30: - `接受 AI 建议` 用于无需修改正文即可确认的结论；`修改后接受` 表示仍需等待候选 Patch。

32: ## 3. 智能复审并接受候选 Patch
33: 
34: 产品回复完成后运行“智能复审”。AI 会检查回复是否真正覆盖原问题，并生成基于精确 `baseCommit` 的候选 Patch。打开“修改建议”，预览完整候选规范，确认变更范围和 AC 后由人工点击接受。
35: 
36: ![审核并接受候选 Patch](assets/demo-03-patches.png)
37: 
38: AI 只能提议 Patch，不能直接写 Git。人工接受后插件创建新 commit，并自动触发 change review；基于旧 commit 的候选 Patch 会失效。
39: 
40: ## 4. 记录 Decision 并确认产品版本
41: 
42: 对状态生命周期、范围边界或新增 AC 等关键选择，在“确认决策”中记录 Decision。Decision 与普通评论分离，包含结论、理由、确认人及受影响章节或 AC。
43: 
44: ![人工确认的产品 Decision](assets/demo-04-decisions.png)
45: 
46: 产品二审无当前版本阻塞项后进入“产品确认”，由产品确认当前 commit。任何后续正文修改都会使受影响的确认失效，必须重新确认。
47: 
48: ## 5. 研发预审、双角色确认和 Ready
49: 
50: 进入“产研共审”后运行“研发智能预审”。工程侧重点核验当前实现、共享组件影响、测试落点、浏览器矩阵及历史约束。演示工作区没有目标业务仓库源码，因此相关项被明确保留为非阻塞 `TO_VERIFY`，而不是虚构实现证据。
51: 
52: 研发确认与产品确认必须绑定同一个当前 commit。随后点击“生成就绪规范”，只有以下六项全部通过才能生成 Ready Spec：
53: 
54: - 目标与用户结果
55: - 验收标准
56: - 范围与非范围
57: - 业务语义
58: - 证据来源
59: - 测试约束

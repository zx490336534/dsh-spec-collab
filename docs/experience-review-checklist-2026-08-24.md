## v0.3.0 验收结果

验收日期：2026-08-24

- 自动化：88 项单元、Engine/API 与 React 测试；Playwright 10/10 通过，覆盖 1440、1280、1024、960、900、680、650 七档视口、移动专注模式、Portal 主题和 44px 热区；axe 无严重或致命违规。
- 状态包：ego 真实宿主确认 `/state` 返回 2 条紧凑摘要与 1 条当前需求视图，摘要不再携带正文、评论、补丁或评审数组。
- ego 真实宿主：验证三栏/双栏/单面板切换、无页面级横向溢出、44px 热区、身份弹窗焦点、草稿导航保护、评论筛选、版本比较、AI 原子补丁、洞察、决策、Ready 导出、个人工作台和对象深链。
- 数据与 Git：验证 v2→v3 原子迁移与备份、未知/损坏 schema 阻断、幂等洞察导入、版本恢复创建新 commit、AI 补丁原子接受。
- AI 会话：同一需求同一阶段的审核、评论分析和追问复用一个 session，仅追加增量提示；进入新阶段后使用新的阶段周期与 session。
- 最新截图：README 中五张流程图已由本次 1440×900 ego 验收截图替换。

## 优先级说明

- **P0**：阻断使用、可能导致数据丢失，或可能让用户错误确认需求。
- **P1**：核心流程明显低效、难理解或存在较高误操作风险。
- **P2**：影响规模化协作、体验一致性、视觉质量或无障碍能力。

## 对照基准

| 产品 | 值得借鉴的模式 | 本插件的主要差距 |
| --- | --- | --- |
| [Linear Project Documents](https://linear.app/docs/project-documents) | Spec、项目资源和进度集中；选中文字即可评论；评论可回复、解决；文档支持协同编辑和版本恢复 | 当前评论入口不易发现，需求、讨论、版本与交付在窄栏中分散，缺少订阅/通知和恢复入口 |
| [Notion Comments](https://www.notion.com/en-gb/help/comments-mentions-and-reminders) | 同时支持页面级讨论和行内评论；可 @ 提及；已解决评论可筛选、重开 | 当前主要依赖选中文字发起讨论，没有页面级总评、@ 提及、筛选和重开入口 |
| [Confluence Comments](https://support.atlassian.com/confluence-cloud/docs/comment-on-pages-and-blog-posts/) | 评论面板统一汇总行内/全局评论，支持未读、打开、已解决筛选、排序、深链 | 当前讨论列表缺少搜索、筛选、排序、未读态和可分享深链 |
| [Confluence Version Comparison](https://support.atlassian.com/confluence-cloud/docs/create-edit-and-publish-a-page/) | 任意选择两个版本比较；明确高亮差异；大段未变内容折叠 | 当前在约 320px 侧栏中并排展示两份全文，没有真实 diff，无法快速判断变化 |
| [GitHub Pull Request Reviews](https://docs.github.com/en/pull-requests/get-started/reviewing-pull-requests-quickstart) | 逐行评论、建议变更、批量提交 review，明确“评论/批准/请求修改”结论 | 当前 AI 建议只有完整候选正文，缺少逐段 diff、分块接受和一次性 review 总结 |
| [Productboard Insights](https://support.productboard.com/hc/en-us/articles/360056354514-Link-user-feedback-to-related-feature-ideas-using-insights) | 用户原声片段与 feature 建立可追溯关联，并记录重要度以支持优先级 | 当前来源只作为文本/链接存在，缺少来源片段到目标/范围/AC 的可视映射和重要度 |

## P0：先修复阻断和数据风险

- [x] **UX-001（P0｜响应式）修复 681–1080px 区间的横向裁切。** 1024×768 实测时，宿主侧栏 + 需求栏 + 正文 + 协作栏同时展开，协作栏右半部分直接超出可视区域，页面也没有横向滚动条。验收：常见 768/900/1024/1280/1440 宽度均能访问全部主操作；空间不足时自动折叠为抽屉或切换到双视图，不依赖用户先发现三个收起按钮。

- [x] **UX-002（P0｜草稿安全）切换需求、返回聊天、查看归档和关闭插件前增加未保存保护。** 当前点击另一条需求会直接替换编辑器内容；代码路径没有 dirty guard，存在静默丢失正文草稿的风险。验收：出现“保存 / 放弃 / 继续编辑”确认，或自动保存可恢复草稿；刷新后也能恢复未提交内容。

- [x] **UX-003（P0｜版本审阅）把版本比较改成真正的全屏/大抽屉 diff。** 当前约 320px 的协作栏再切成左右两列，每列仅约 150px，且只是两份全文并排；长 URL、表格和中文段落均不可读。验收：新增/删除/修改高亮，默认折叠未变化段落，可在任意两个版本间比较，并能从差异定位到正文。

- [x] **UX-004（P0｜AI 建议安全）接受 AI 建议前展示基于 `baseCommit` 的可审阅 diff。** 当前“查看修改后的完整正文”只展开整篇候选稿，用户很难识别 AI 是否顺带改了未讨论内容。验收：逐段显示 before/after、受影响章节和 AC；支持分块接受/拒绝或至少明确列出全部变化；基线过期时阻止接受。

- [x] **UX-005（P0｜弹窗）身份登记弹窗必须可取消。** 实测弹窗没有关闭/取消按钮，点击后只能填写花名保存；Esc 也无效，整个插件被锁住。验收：提供关闭按钮和取消按钮，支持 Esc、点击遮罩（如产品规则允许），关闭后恢复触发按钮焦点。

- [x] **UX-006（P0｜移动端）补齐窄屏需求导航。** ≤680px 时需求列表被完全隐藏，只剩“需求正文 / 下一步”，无法切换需求、新建需求或查看归档。验收：标题区提供需求选择器/抽屉，覆盖搜索、切换、新建、归档；操作后仍停留在移动视图。

## P1：核心流程与信息架构

- [x] **UX-007（P1｜定位）切换需求/版本后重置或按需求恢复正文滚动位置。** 实测从滚到底部的「社区二期」切换到 Ready 示例后，仍停留在新文档底部的 Open Questions，用户看不到标题和目标。验收：首次打开默认到顶部；再次返回同一需求可选择恢复各自位置；从问题定位进入时仅按明确锚点跳转。

- [x] **UX-008（P1｜数量口径）统一“9 项待处理 / 10 个待回答 / 12 个问题 / 5 个关键问题”的定义。** 同一屏同时出现多个相近数字但没有解释范围，用户无法判断剩余工作量。验收：统一主口径；历史、待核对、阻塞、与我相关分别标注并提供 tooltip/说明。

- [x] **UX-009（P1｜流程命名）统一“澄清 / 产品审核 / 下一步 / 完成条件 / Ready”等阶段词汇。** 当前阶段 rail、需求卡片、页脚、侧栏使用不同词，且中英文混用。验收：建立一套阶段字典，所有入口展示同名状态，并说明进入下一阶段的条件。

- [x] **UX-010（P1｜评论入口）增加可发现的“评论”入口和页面级总评。** 目前发起新讨论依赖用户在正文选中文字，首屏没有提示；无法对整篇需求给出总评。验收：正文悬浮工具条/快捷键提示清晰可见；支持页面级评论与行内评论，并在统一面板中区分。

- [x] **UX-011（P1｜评论管理）为讨论增加打开/已解决/未读筛选、排序和重开。** 当前只能通过当前讨论、已处理和历史分组浏览，需求变大后难以收口。验收：支持状态筛选、按正文顺序/时间排序、已解决重开，并保留处理人和处理时间。

- [x] **UX-012（P1｜协作触达）增加 @ 提及、关注/订阅、指派人与通知。** 当前问题只显示角色相关任务，缺少把具体问题交给具体人的机制。验收：评论/问题可 @ 人或分配 owner，展示截止阶段/日期；被提及、回复、状态变化时进入宿主通知或待办。

- [x] **UX-013（P1｜深链）为需求、章节、AC、问题、评论、决策和版本提供可复制链接。** 当前无法把某条待回答问题或某个正文锚点精准分享给同事。验收：复制链接后可恢复需求、当前标签、对象选中态和正文位置；无权限时给出明确提示。

- [x] **UX-014（P1｜来源追溯）把来源片段显式关联到目标、规则和 AC。** 当前来源以 URL/文件文字展示，用户难以判断哪条结论来自哪段证据。验收：每个关键结论可展开查看来源片段、版本、可访问性、采纳人和重要度；反向可从来源看到影响的章节/AC。

- [x] **UX-015（P1｜坏链接）修复裸文件名被错误解析为外链。** AI 检查记录中的 `AGENTS.md`、`README.md` 被渲染成 `http://agents.md/`、`http://readme.md/`，点击会离开本地上下文。验收：本地文件显示为不可点击代码样式或打开可信本地文件；只有合法 http(s) URL 才生成外链。

- [x] **UX-016（P1｜文本完整性）修复摘要按字节截断产生的 `�...`。** 实测 AI 检查摘要出现“匿名浏览与�...”。验收：按 Unicode 字符/字素簇截断，中文、Emoji、组合字符均不产生替换字符。

- [x] **UX-017（P1｜决策空状态）关键决策为空时提供解释性空状态。** 当前面板只剩“记录新决策”按钮和大片空白，不说明何时需要 Decision、与评论有什么区别。验收：展示适用场景、示例和“从当前问题形成决策”的入口。

- [x] **UX-018（P1｜决策表单）缩短决策录入并固定底部操作栏。** 870px 高度下三个大 textarea 已把取消/保存按钮推到屏幕外；章节和 AC 还需继续滚动。验收：字段按内容自适应高度，受影响章节/AC 用可搜索选择器，取消/保存 sticky，必填原因就近提示。

- [x] **UX-019（P1｜历史）版本列表不要把当前版本作为“历史版本”可比较项。** 当前点击最新 commit 会出现“历史版本 90bc325d / 当前版本 90bc325d”的无意义对比。验收：当前版本禁用或标注“当前”，默认选中上一个版本，并允许用户选择任意两个不同版本。

- [x] **UX-020（P1｜历史恢复）增加“恢复为新版本”与撤销路径。** 现在只能查看历史，无法从 UI 恢复；删除说明虽称 Git 可恢复，但没有产品内入口。验收：恢复操作创建新 commit、不抹掉历史，展示影响的确认/决策失效范围，并允许立即撤销误归档。

- [x] **UX-021（P1｜交付）Ready Spec 增加复制、下载 Markdown、查看 Git 版本和分享入口。** 当前只能在窄侧栏中阅读“交付需求”，不利于进入研发流程。验收：可一键复制/下载，产物包含 commit、package hash、确认人、决策与 Open Questions，并能回到对应版本。

- [x] **UX-022（P1｜全局查找）为需求列表和协作对象增加搜索、筛选、排序。** 当前需求稍多后只能滚动寻找，问题/讨论/决策也无法按类型、状态、负责人过滤。验收：至少支持标题/正文搜索、阶段/阻塞/与我相关筛选、最近更新排序，并记住个人视图。

- [x] **UX-023（P1｜归档）归档改为可撤销操作。** 当前更多菜单中的“归档需求”点击后立即执行并切走，误触成本高。验收：成功后 toast 提供“撤销”，并明确归档不会删除 Git 历史；移动端也能找到归档入口。

- [x] **UX-024（P1｜新建校验）为新建需求提供就地错误提示和提交前摘要。** 当前依赖浏览器原生 required 气泡，没有持久错误说明；按钮文案会立即开始 AI 检查，但未说明预计耗时、会读取哪些工作区资料。验收：每个字段就地报错，提交前可确认工作区与资料范围，提交后显示可取消/可离开的进度。

- [x] **UX-025（P1｜状态反馈）长耗时 AI 操作显示统一进度、开始时间和失败恢复。** 当前 AI 运行信息散落在宿主会话、检查记录和页脚，用户不清楚是否可离开。验收：任务卡显示排队/运行/成功/失败、耗时和重试；离开页面不丢任务；失败保留输入和可读原因。

## P2：交互细节、视觉与无障碍

- [x] **UX-026（P2｜聚焦模式）把“收起需求栏 + 收起协作栏”整合成明确的正文聚焦模式。** 手工折叠后正文阅读体验明显改善，但入口分散在左右两个小箭头。验收：单个“聚焦正文”动作可进入/退出，并恢复之前栏宽；支持快捷键。

- [x] **UX-027（P2｜自适应布局）根据可用宽度自动调整栏宽和正文排版。** 三栏全开时正文仅约 380px，30px 标题、较大左右 padding 和长 URL 导致频繁断行。验收：正文保留合理阅读宽度；不足时协作栏变 overlay；标题、间距、表格和 URL 在各断点下均可读。

- [x] **UX-028（P2｜层级精简）减少顶部重复状态层。** 阶段 rail、编辑工具栏、协作指标条、右侧 workflow 卡和页脚同时表达进度，占用大量垂直空间。验收：首屏只保留“当前阶段 + 下一动作 + 风险数量”三个核心信号，详细状态按需展开。

- [x] **UX-029（P2｜状态语义）不要主要依赖颜色和单字符锚点表达问题。** 正文旁的 `!`、`?` 和小色块需要用户猜测含义。验收：hover/focus 显示类型、严重度和标题；屏幕阅读器读出完整名称；高对比度模式仍可区分。

- [x] **UX-030（P2｜触控目标）扩大图标按钮、正文锚点和折叠箭头的可点击区域。** 多个控件只有 24–30px，窄屏和触控板上容易误触。验收：主要触控目标至少 44×44px，视觉图标可保持小尺寸但热区扩大。

- [x] **UX-031（P2｜分栏键盘操作）让两个分栏拖拽条可聚焦并支持键盘调宽。** 当前 separator 仅实现 pointer drag，键盘用户无法调整。验收：`tabIndex=0`，方向键按步进调整，Home/End 恢复最小/最大，暴露 `aria-valuenow/min/max`。

- [x] **UX-032（P2｜弹窗无障碍）统一所有弹窗的语义、焦点圈定和退出行为。** 普通 modal 只是外层 `div`，没有统一 `role="dialog"`、`aria-modal`、标题关联与 focus trap。验收：打开后焦点进入，Tab 不逃出，Esc 关闭可取消弹窗，关闭后恢复焦点；高风险确认保留明确按钮。

- [x] **UX-033（P2｜动态播报）为保存、AI 运行、错误、评论提交和阶段变化增加 `aria-live`。** 当前 notice/页脚只是视觉文本，屏幕阅读器可能感知不到。验收：成功用 polite、阻断错误用 assertive；重复 SSE 刷新不反复播报同一消息。

- [x] **UX-034（P2｜Tab 键盘模型）按 WAI-ARIA tabs 模式补齐左右键切换与 roving tabindex。** 当前 tab 使用普通 button，能 Tab 到达但需要逐个 Tab。验收：左右键切换同组标签，Home/End 跳首尾，选中态与焦点同步。

- [x] **UX-035（P2｜滚动可见性）不要隐藏可横向滚动区域的滚动条而不提供替代提示。** 协作指标和标签在窄宽度下可横滚但滚动条隐藏，用户不知道还有内容。验收：提供渐隐提示/左右箭头或自动换行，并保证键盘可滚动。

- [x] **UX-036（P2｜编辑可发现性）明确正文处于可编辑状态，并提供轻量格式/快捷键帮助。** 当前视觉上像只读文档，只有“保存版本”暗示可编辑。验收：进入编辑时有清晰状态、常用 Markdown/格式入口和撤销/重做；只读用户显示明确只读态。

- [x] **UX-037（P2｜保存说明）把“说明本次改动”从 placeholder 升级为可见标签，并解释按钮禁用原因。** 当前空值时“保存版本”灰掉，用户需要猜测还缺变更说明还是正文没有变化。验收：可见 label/辅助文案，disabled reason 可读，Cmd/Ctrl+S 触发同一校验。

- [x] **UX-038（P2｜时间与作者）统一时间格式并支持相对/绝对切换。** 版本历史使用完整本地时间，宿主会话使用“几分钟前”，讨论卡片又缺少醒目更新时间。验收：列表默认相对时间，hover 展示绝对时间和时区；所有记录显示创建者、最后处理者。

- [x] **UX-039（P2｜工作量视图）增加“与我相关”聚合视图。** 当前单条需求内有任务队列，但跨需求无法快速看到本人待回复、待确认、待复核项。验收：全局待办按阻塞程度和阶段排序，可直接跳转对象，并支持批量标记已读。

- [x] **UX-040（P2｜质量回归）建立核心体验的视觉与键盘回归用例。** 验收至少覆盖：1272/1024/900/680/650px、三栏展开/折叠、身份弹窗退出、未保存切换保护、历史 diff、移动端需求切换、键盘完成评论与回答流程。

## 建议实施顺序

# 使用说明

## 创建并完成产品澄清

1. 打开 DSH 侧栏的「需求讨论」，从需求库新建需求。首次写入时登记花名和角色。填入原始描述、工作区和可选的参考资料；创建动作会保存首个 Git 版本并发起产品初审。
2. 在「下一步」中回答 AI 提出的问题。可以定位原文和依据，为无法验证的内容保留待核对状态。回答完后点击「让 AI 回读并生成修改」。
3. 在「AI 建议」中打开差异，核对改动对应的章节和验收标准。接受候选修改会创建新 commit，并触发变更审核。也可以直接编辑正文，填写改动说明后保存。
4. 按「下一步」完成当前版本的产品审核、产品确认，再进入产研共审。关键取舍可在「记录」中保存为决策，保留结论、理由和影响范围。

## 研发共审与交付

1. 运行当前版本的研发检查，处理阻塞问题和待审修改。
2. 产品与研发分别确认当前 commit。章节或验收项的确认用于局部协作，整版确认用于生成 Ready。
3. 在「完成条件」检查目标、范围、业务规则、验收标准、证据与测试约束，全部通过后生成 Ready。
4. 点击「查看交付内容」，可以复制 Markdown、下载 `.md`、复制 commit 或分享。正文再次修改后，旧交付包、整版确认和待处理候选修改失效。

## 协作入口

- 选中正文可以添加批注。「讨论」汇总评论、回复和提及。「我的工作」汇总跨需求待办。
- 「记录」可查看 Decision 和 Git 历史。恢复历史会生成一个新版本。并发编辑触发冲突提示，本地草稿仍可恢复。
- 「洞察」可以记录或导入客户反馈，并关联需求、章节或验收项。单次最多 2,000 条或 5 MB。[CSV 模板](insight-import-template.csv) · [Markdown 模板](insight-import-template.md)
- `Cmd/Ctrl+S` 保存正文。`Cmd/Ctrl+Shift+F` 切换正文专注模式。窄屏使用「需求正文 / 协作」切换。
